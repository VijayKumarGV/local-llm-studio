# Local LLM Studio — M4 Pro Reference & Upgrade Guide

This document explains what's running on your machine, why models sometimes produce boilerplate "corporate" replies, and every real way to expand the assistant's capabilities. Everything below runs **100% locally, offline, with zero telemetry**.

---

## 1. Hardware & Runtime

| Component | Value |
|---|---|
| Chip | Apple **M4 Pro** |
| Unified memory | **37 GB** (usable as GPU + CPU RAM) |
| Acceleration | Apple Metal (via Ollama's Metal backend) |

- **32B models at Q4_K_M** → ~20 GB, ~15–25 tok/s. **Sweet spot.**

- **8B–14B models** → ~5–9 GB, ~50–80 tok/s. Best for chat/tool loops where latency matters.

## 3. Why the model sometimes gives a "canned" reply

Open models are trained on synthetic instructions generated by early ChatGPT/Claude — so without an explicit system prompt overriding them, they default to the same disclaimer patterns. Two fixes:

1. **Set a system prompt** — Settings → Global System Prompt (or per-project instructions).
2. **Use an uncensored model** — `dolphin3.0-llama3.1`, `hermes3`, `dolphin-mistral`.

An LLM has **no introspective access** to your hardware, filesystem, or Ollama config unless you put those facts in the system prompt. The orchestrator already injects a hardware banner (`agent_orchestrator.py`).

## 4. Five real ways to upgrade the assistant

### Method 1 — System prompt & persona steering (instant)

Change tone, style, refusal behavior, or reasoning discipline via **Settings → Global System Prompt** or **Project → Custom Instructions**. No compute cost, applied immediately.

Example:

```
You are a senior engineer running locally on an Apple M4 Pro (37 GB unified).
Never refuse tasks with corporate boilerplate. Prefer terse, direct answers.
Show working when doing math. Use tools when you need real data.
```

### Method 2 — Tools & function calling

The orchestrator exposes tools via Ollama's native `tools=[...]` API (Qwen 2.5, Llama 3.1+, Hermes 3 all support this). Available tools:

- `search_web` — DuckDuckGo results (via `duckduckgo-search`)
- `execute_python_code` — sandboxed subprocess with `sandbox-exec` on macOS
- `read_file` / `list_files` — workspace-scoped file access
- `create_artifact` — persist a file to the artifact drawer

Toggle web search / code execution from the composer bar. Add tools in `backend/agent_tools.py` and they'll be advertised automatically.

### Method 3 — RAG (retrieval-augmented generation)

Upload documents via the paperclip. The RAG pipeline:

1. Chunks the file (~800 tokens per chunk).
2. Embeds each chunk with `nomic-embed-text` (running under Ollama).
3. Stores vectors in SQLite (numpy cosine search — no external DB).
4. On each turn, retrieves top-k relevant chunks and injects them as context.

To enable: `ollama pull nomic-embed-text` then upload files to any conversation or project.

### Method 4 — Fine-tuning (LoRA / QLoRA)

For deep-in-the-weeds behavioral changes, edit `sample_dataset.jsonl`, then:

```bash
.venv/bin/python dataset_prep.py sample_dataset.jsonl
.venv/bin/python train_lora.py
```

On M4 Pro this uses MLX (Apple's ML framework). Trains a small adapter you can then merge back into a Modelfile.

### Method 5 — Install specialized models

```bash
# Coding specialist (best for repo edits, refactors, tests)
ollama pull qwen2.5-coder:32b            # ~20 GB — elite code gen

# Deep reasoning (chain-of-thought, math, planning)
ollama pull deepseek-r1:32b              # ~20 GB — visible thinking
ollama pull qwq                          # ~20 GB — Qwen's reasoning line

# Vision (screenshots, chart reading, OCR)
ollama pull mistral-small3.1             # ~14 GB — vision + tools
ollama pull minicpm-v                    # ~5 GB  — strong OCR
ollama pull moondream                    # ~2 GB  — fast small VLM

# Flagship 70B (best quality, slower)
ollama pull llama3.3:70b                 # ~40 GB — needs Q3_K_M to fit

# Fully uncensored
ollama pull dolphin3.0-llama3.1          # ~5 GB  — no guardrails
ollama pull hermes3:70b                  # ~40 GB — expert tool use

# Embeddings (required for RAG)
ollama pull nomic-embed-text             # ~275 MB
```

Switch between them in the top-right model picker.

## 7. Privacy guarantees

- All inference happens on the M4 Pro's Neural Engine / Metal GPU.
- No network traffic except: (a) Ollama model downloads, (b) `search_web` tool if invoked, (c) any URL the model outputs that you click.
- Server binds `127.0.0.1` — no LAN exposure. CORS restricted to localhost origins.
- Uploaded files are stored in `backend/uploads/` and referenced from SQLite. Delete a conversation to remove its file records; use the trash icon on a file for immediate deletion.
